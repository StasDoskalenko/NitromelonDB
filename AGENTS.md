# AGENTS.md

NitromelonDB (`nitromelondb`) is a reactive SQLite database for React Native and web — a maintained fork of WatermelonDB. Nitro / New Architecture only. Docs: https://stasdoskalenko.github.io/NitromelonDB/

## The git root is the library, not an app

| What                            | Where                       | Run                                                            |
| ------------------------------- | --------------------------- | -------------------------------------------------------------- |
| Library (the published package) | git root: `src/`, `native/` | `yarn test` · `yarn build`                                     |
| iOS/Android example (Expo)      | `examples/NotesApp`         | `cd examples/NotesApp && yarn expo run:ios` (or `run:android`) |
| Windows example (RNW)           | `examples/NotesApp_windows` | see its `AGENTS.md`                                            |
| Sync server (e2e, benchmarks)   | `examples/sync-server`      | `yarn start:notes-app`                                         |

Each example is its own package with its own `AGENTS.md`. `cd` there first.

- Never run Expo, Metro, or Maestro from the library root.
- Before starting Metro anywhere, check port **8081** (`lsof -i :8081` or `curl -s http://localhost:8081/status`). If it is running, reuse it. Never start a second one.
- Never hand-edit `dist/` or `nitrogen/`. They are generated by `yarn build` and `yarn specs` (run `yarn specs` after Nitro spec changes).

## Library commands

```bash
yarn eslint && yarn typecheck
yarn lint:workflows             # after editing .github/workflows
yarn test:ios / yarn test:android   # native SQLite/adapter integration tests
```

Yarn 4.18, Node ≥ 22. Do not add `package-lock.json`.

## Conventions

- Behavior changes need Jest tests under `src/**/__tests__`. Native SQLite/adapter work also needs `yarn test:ios` / `yarn test:android`.
- `yarn prettier` before commit. Changelog entries go in `CHANGELOG-Unreleased.md`.
- No Paper/legacy bridge. No parallel `.d.ts` layer.
- `skills/` holds agent skills for apps that _use_ the library (`npx skills add StasDoskalenko/NitromelonDB`), not for working on this repo. One folder per skill, named like its `name:`. Keep them in step with the docs they follow, and list new ones in `docs-website/docs/docs/AgentSkills.md`.
- Native setup and troubleshooting: `CONTRIBUTING.md`.
